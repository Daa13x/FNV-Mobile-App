# Bridge protocol v1 (Pass 6)

Endpoints:

- `GET /health` — public `{status, mode, protocol}`. Modes: `mock`, `external_snapshot`, `ayn_read_only`.
- `POST /v1/pair` — JSON `{"code":"123456"}` **or** `{ "qr_secret":"32-character-base64url-secret" }` (never both); returns bearer token on success. Pairing code valid for ten minutes from bridge launch/last successful pairing, one-use and regenerated after success. Five failed attempts per IP within 60 seconds return HTTP 429.
- `GET /v1/snapshot` — requires `Authorization: Bearer <token>`. Reads the currently selected source and returns transformed v1 data or HTTP 503 when unavailable. Never substitutes mock values for failed live sources.
- `POST /v1/unpair` — requires same bearer token; removes that token. No request body required.

No inventory action, item-use, fast-travel, quest write or radio control endpoint exists. No authenticated token persistence. Plain HTTP is **not production secure**.

## AYN interoperability

The bridge's AYN adapter calls **only** `GET http://127.0.0.1:<port>/state` on the PC. It optionally sends `X-AYN-Token` from `PIPBOY_AYN_TOKEN`. It neither copies nor edits upstream source. It does not call `/action`, `/settings` or any file-modification route.

Upstream's `ready` must be true, `game` must be `FalloutNV`, `tick` a nonnegative integer, `player` an object, and `inventory` an object. Invented values are not inserted for unknown game fields. `sequence` equals the upstream tick; `bridgeReadAtUnixMs` is an observation timestamp generated by our bridge, not proof the game progressed.

The optional upstream settings and schema are documented at:
https://github.com/Abacus1829/ayn-dual-screen/blob/main/falloutnv/src/Dtos.h

External snapshot-file input is explicitly labelled `external-file-unverified` because a file may be stale or fabricated.

## QR invitation contract (Pass 6)

The bridge can generate `pipboyremote://pair?v=1&host=<private-IPv4>&port=8765&secret=<one-use-secret>` only on the *PC screen*, not over unauthenticated HTTP. The random secret is 192 bits, valid at most 120 seconds and consumed on successful pairing. Invalid attempts share the manual-code rate limit. Android validates all parameters and rejects external addresses and unsupported ports. See `PASS6_QR_PAIRING.md`.
